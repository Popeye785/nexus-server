## Warum (Engineering-Analyse)

### 1. Default-Parameter sind nicht profitabel

Default `sl=2%, tp=4%` = 1:2 R/R-Verhältnis. Bei diesem R/R braucht man **≥34% WR** für PF≥1.0. Alle Strategien haben **31-37%** WR — marginal an der Grenze. Mit Fees+Slippage rutscht PF unter 1.0.

### 2. Strategien selbst sind sehr primitive

```js
ema_cross: signal = e20 > e50 && pe20 <= pe50      // EMA-Kreuzung
ichimoku:  signal = ich.bullish && !ich.inCloud     // Bullisch ohne Cloud-Berührung
patterns:  signal = ps.direction==='BUY' && ps.strength>0.7  // Pattern-Recognition
funding_arb: signal = rsi<35 && close<bb.lower      // Oversold + BB-unter
```

Das sind **single-indicator Trigger ohne Trend-Filter**. Für ein professionelles Trading-System ist das zu naiv.

### 3. Live-Bot nutzt komplexere Logik

Der **Live-Bot trainiert seine ML-Modelle aus echten Live-Trades** (z.Z. 435 Samples in `ml_models.trained_on`), die UnifiedScore + Brain + alle 21 Quellen + Regime-Adapter etc. nutzen. **Diese Komplexität wird vom Backtest-Pfad nicht repliziert.**

### 4. Filter-Schwelle ist korrekt kalibriert

PF ≥ 1.2 ist Industry-Standard. Christian's eigene Spec sagt explizit "PF > 1.2 Pflicht. Nur dann Modelle übernehmen." Mein Skript hat genau das richtig gemacht und Rollback durchgeführt.

✅ **Positiv:** Das Anti-Brick-System funktioniert. ML-Modelle sind sauber, Bot stabil.
