## ROOT-CAUSE

Backend war OK seit T0.6-Deploy gestern (`requireDeployToken` Middleware respektiert `bot_settings.deploy_token_required`).

**Bug lag im Frontend:** 4 unabhängige `sessionStorage.getItem('deployToken')` + `prompt(...)` Stellen die IMMER nach Token fragten, OHNE den Server-Toggle-Wert zu prüfen:

| Stelle | Funktion |
|---|---|
| `index.html:3989-3996` | `_nxGetDeployToken()` — zentrale Helper für `apiV9()` |
| `index.html:4968-4972` | `setDeployMode()` — Deploy-Mode-Wechsel |
| `index.html:5392-5396` | `_deployTokenOrPrompt()` — Kill-Switch + andere |
| `index.html:7816-7821` | `toggleDemoLive()` — DEMO↔LIVE-Switch |

Plus: `sessionStorage` ist **tab-local** → Inkonsistenz zwischen Handy- und Mac-Browser.

---

## FIX

### 1) Server-authoritative Cache im Frontend

Neu in `index.html`:
```js
window.__NX_TOKEN_REQUIRED = false;  // default sicher
async function _nxRefreshTokenRequired() {
  const r = await fetch('/api/config/deploy-token');
  const j = await r.json();
  window.__NX_TOKEN_REQUIRED = !!(j && j.required);
}
// Beim Page-Load + alle 30s (Cross-Browser-Sync)
setTimeout(_nxRefreshTokenRequired, 500);
setInterval(_nxRefreshTokenRequired, 30000);
```

### 2) Alle 4 Token-Prompt-Stellen respektieren jetzt den Toggle

```js
function _nxGetDeployToken() {
  if (!window.__NX_TOKEN_REQUIRED) return '';  // bypass komplett, KEIN Prompt
  // sonst wie bisher: sessionStorage → prompt → store
}
```

`apiV9()` + `setDeployMode()` + `_killApiCall()` + `toggleDemoLive()` alle nutzen jetzt:
- `const token = _nxGetDeployToken();`
- `if (token) headers['X-Deploy-Token'] = token;`  ← conditional header

### 3) `toggleDeployToken()` updated Cache sofort

```js
window.__NX_TOKEN_REQUIRED = !!j.required;  // sofort, ohne 30s-Wartetimer
if (newState) sessionStorage.removeItem('deployToken');  // bei Aktivierung Token-Reset
```

### 4) ANTI-BRICK: Confirm-Phrasen BLEIBEN

LIVE-Switch-Bremsen sind unabhängig vom Deploy-Token-Toggle:
- `LIVE BESTAETIGEN` UX-Confirm (Z.7827)
- `I_UNDERSTAND_LIVE_MEANS_REAL_MONEY` Backend-Confirm-Phrase (Z.7831)

Diese werden auch bei Toggle=AUS immer abgefragt für LIVE-Switches. Begründung: Real-Geld-Schutz darf NICHT durch User-UI-Toggle bypassbar sein.
